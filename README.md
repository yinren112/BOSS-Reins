# BOSS-Reins

**The model writes. Reins decides when to act.**

BOSS-Reins 是一个给小模型套上缰绳的 harness：模型只负责写开场白，什么时候发、发几条、发不发，全部由确定性的脚手架决定。它跑在 BOSS 直聘上，目标是替独立开发者找到"想直接找人把软件做出来"的客户并发出第一句招呼；后续沟通由本人接管。

这不是一个 prompt 集合，也不是一个浏览器脚本。它是一套让不可靠的模型在有风控的平台上安全干活的约束系统，每一条规则都来自一次真实的翻车。

## 为什么需要 harness

直接让模型驱动浏览器会遇到三件事：

1. **模型不知道什么叫"够了"。** 它会为了凑数把额度刷到平台封号线。
2. **模型会编。** 让它写 80 条开场白，30 条写同一个金额，25 条写同一个数字，还会往上凑没做过的技术名。
3. **模型的状态活在上下文里。** 上下文一压缩，它就忘了今天发过谁、锁有没有解、上次翻到第几页。

Reins 的答案是把这三件事全部从模型手里拿走：

| 问题 | 机制 | 位置 |
|---|---|---|
| 不知道够了 | 24 小时滚动预算 + 10 分钟突发上限 + 最小随机间隔，三层闸门，跨进程、跨重启生效 | `workflow/safety.js` |
| 会编 | 事实白名单门禁：只放行事实文件里出现过的项目名和场景词，禁写被刷烂的数字，禁写未确认技术名，同日重复问句/开头/项目锚点限频 | `workflow/opener-service.js` |
| 状态在上下文里 | 外置台账 + 熔断锁文件 + 离线回放命令，模型每次只看一个快照 | `workflow/ledger-store.js`、`data/lock.*.json` |
| 模型陪着一条条发太贵 | 计划文件 + 确定性执行器：模型离线批量写材料，人看一眼计划，执行器逐条发、异常即停、断点续跑 | `workflow/dispatch.js` |
| 规则改坏了没人知道 | 用真实成交过的 JD 做回归基线，任何规则把它们判成不可发送就是规则错了 | `workflow/self-test.js` |

## 架构

```
┌──────────────────────────────────────────────────────────────┐
│  模型（Codex / Claude Code / 任意 CLI 模型）                    │
│  只做两件事：读 JD 写审核结论；按事实卡写开场白                     │
└───────────────┬──────────────────────────────────────────────┘
                │ 只能通过 node workflow/boss.js <命令> 动手
┌───────────────▼──────────────────────────────────────────────┐
│  Reins 内核                                                    │
│  ├ safety.js        预算 / 熔断锁 / 节流（所有在线命令前置）        │
│  ├ opener-service   事实门禁 / 去 AI 感 / 长度 / 重复限频           │
│  ├ project-scoring  离线粗筛：交付物 + 合作依据 + 无到岗 = 可发送    │
│  ├ dispatch.js      ai-opener --batch → send-plan → dispatch      │
│  ├ ledger-store     台账写锁 + 原子替换 + 乐观并发                  │
│  └ self-test.js     真实成交 JD 回归 + 门禁回归                    │
└───────────────┬──────────────────────────────────────────────┘
                │ 裸 CDP（不用 Playwright，避免反自动化）
┌───────────────▼──────────────────────────────────────────────┐
│  BOSS 适配器：cdp.js / browser.js / page-flows / discovery      │
│  已登录 Edge 独立 profile，隐藏桌面，语义快照，送达证据核验          │
└──────────────────────────────────────────────────────────────┘
```

详细设计见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)，规则的来历见 [docs/LESSONS.md](docs/LESSONS.md)。

## 三层闸门

所有在线动作先过 `reserveAction`，它检查三件事再放行：

| | 搜索页 | 岗位详情 | 发送 |
|---|---|---|---|
| 24 小时作业额度 | 90 | 700 | 120 |
| 24 小时平台硬顶（触顶自动写熔断锁） | 120 | 900 | 150 |
| 10 分钟突发上限 | 6 | 45 | 15 |
| 最小间隔（随机上浮 50%） | 15s | 8s | 30s |

窗口是滚动的，不是日历日，所以跨零点不会清零。硬顶是翻车线不是安全线：实测岗位详情约 1000 次/日封号，900 是留 10% 余量。间隔不满足时脚本自己等，不报错；总量或密度超了才拒绝。

熔断锁是文件，不是内存。验证码、403、账户异常、连续空白 JD 都会写锁；风控级的锁当天拒绝解锁，最早满 24 小时且跨自然日才能解。上下文压缩、重启、换模型都清不掉它。

## 事实门禁

开场白必须同时满足：

- 第一句命中至少一个**事实锚点**（你在 `facts.md` 里写过的项目名或只有做过才说得出的场景词）
- 不含**禁写数字**（那些被模型刷烂的金额和测试数）
- 不含**未确认技术名**（事实源里没有、模型爱往上凑的）
- 不含**套话**（"具备…能力/赋能/高效/一站式/期待合作"）、不用分号分点、顿号串最多 3 项
- JD 没写远程时**必须问一句**能不能远程；问题不能是"目前主要做哪类系统"这种不看 JD 也能问的
- 同一问句、同一开头同日不超过 3 次；同一项目锚点同日不超过「当日总数 ÷ 项目数」
- 120–200 字

模型生成被拒一次，拒绝原因喂回去重写一次，第二次仍不过才放弃。`ai-opener --batch` 末尾会打印拒绝原因分布，哪个门禁拒得最多就是提示词或事实卡该改的地方。

## 批量管道

```powershell
node workflow/boss.js ai-opener --batch     # 离线：给整个审核通过队列生成开场白，逐条过门禁、逐条落台账
node workflow/boss.js send-plan             # 离线：材料就绪队列 → data/plans/plan-*.json，绑定 JD 哈希与开场白哈希
node workflow/boss.js dispatch --plan=...   # 在线：逐条发送，发前重验锁/JD/哈希/门禁，异常即停机，重跑同一文件续跑
node workflow/boss.js dispatch --status
```

`send-plan` 是唯一的人工确认点。`dispatch` 执行期间不需要任何模型在线。

## 快速开始

```powershell
git clone https://github.com/yinren112/BOSS-Reins
cd BOSS-Reins
copy reins.config.example.json reins.config.json   # 填你的显示名、作品链接、简历文件名、事实锚点
copy facts.example.md facts.md                     # 换成你自己的真实项目
copy profiles.example.json profiles.json           # 岗位方向关键词，可直接用
.\start-boss-browser.bat                           # 起一个带 CDP 端口的已登录 Edge，扫码登录
node workflow/boss.js doctor                       # 离线体检：依赖、文件、帮助覆盖、台账、自测
node workflow/boss.js preflight                    # 锁、浏览器、额度、队列总览
```

开场白生成默认调用本机 `codex exec`，用 `BOSS_AI_MODEL` 环境变量换模型。搜索、读 JD、审核的日常流程见 [AGENTS.md](AGENTS.md)，它同时是给模型看的操作手册。

`reins.config.json`、`facts.md`、`profiles.json`、`data/` 全部在 `.gitignore` 里。自测永远跑在 `*.example.*` 上，你的真实数据不会进仓库。

## 数据

- 从零迭代两个月，累计送达 1200+ 条首次招呼，零封号
- 两单真实成交，两份 JD 作为回归基线写进自测
- 每一条规则都能溯源到一次翻车，来历在 [docs/LESSONS.md](docs/LESSONS.md)

## 边界

- 只发首次招呼，不自动回复，不自动发简历。后续沟通由本人接管。
- 不统计回复率：本人自己会回复、也会自己打招呼，系统读不全会话，数据只会失真。
- 这套东西操作的是一个有反自动化措施的商业平台。它的全部设计目标是"像一个谨慎的人"而不是"绕过检测"，但使用它仍然是你自己的账号风险。请先读平台条款。
