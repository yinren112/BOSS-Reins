# 规则的来历

每条规则后面都有一次翻车。按主题整理，同一主题只保留当前有效口径；被覆盖的旧规则在文末表里。

## 1. 目标与指标

- **出口不能关。** 累计送达 1100+ 条时成交 2 单，全部出自每天 50–100 条的发送期；之后十天只发 1 条、读几百条 JD、成交 0。任何"人工复核、不自动发送"的档位等于把管道关死，因为没有人真的去复核。`eligible` 就走审核 → 开场白 → 发送。
- **每日指标只有发送数。** 回复率曾经统计过，后来删掉：本人自己回复、自己也打招呼，系统翻不完几百个会话，数据只会越来越假。
- **两单成交 JD 是回归基准。** 一单 JD 写明"兼职·远程·按单结算"，一单 JD 只有 60 字、写了城市和包吃住、没写远程，靠开场白里一句"远程协作方式可以沟通"接进来。所以：JD 没写远程、没写项目制、没写结算，都不是不发送的理由。
- **不凑数。** 没有合格岗位时 0 就是正确结果；禁止以"凑够 N 条"为目标扩词、翻页、补读。

## 2. 岗位筛选

- "未写远程"记 `negotiable`，开场白里问；只有明确到岗/坐班/驻场才 `fail`。早期把"非居家办公"误记为远程、把"未写远程"判成 fail，两个方向都错过。
- 接单池、合作意向岗位的核心栈错位不淘汰；"Python 或 Node 或 Java 任一门熟"这类多选栈不算错位。
- 公司规模 ≥500 人排除；小团队明确软件定制时，"高级/资深/3 年以上"不单独淘汰。
- 标题隐藏真实职责（主播、直播、销售转化）要靠正文判，不按标题一刀切。
- 硬红线只保留真实风险：猎头隐藏客户、收费、拉人头、分红股权、销售伪装、夜班、骗局、截止日期已过、标注/训练数据/实习。

## 3. 搜索与发现

- 入口优先级：收藏 → 推荐流 → 关键词搜索 → 公司在招 → 详情页顺带的相关岗位。先清队列再搜索。
- 技术泛词（"Python 兼职"、"前端 远程"）存量池污染严重，读完常触发"已存在会话"或已过期，废弃。
- 老板视角大词（"兼职程序员"、"找程序员"）是另一类：掏钱买工具的小老板不懂技术词，标题只会打土词。污染源是培训噪音而非存量池，配最新排序即可过滤。
- 入库率不是成交率。某些词入库多但零回复，观察期内不得写成核心入口。
- 搜索页是 SPA 瀑布流，`?page=N` 被忽略；列表卡片只渲染约 15 条；薪资用字体混淆，列表页拿不到明文。一条命令只推进一页，翻页断点绑定专用标签。

## 4. 开场白

- **一天 80 条开场白里 30 条写同一个金额、32 条写同一个测试数、25 条写同一个页面数。** 锚点门禁被同一组数字刷过去，对老板没说服力还立了低价锚。这些数字永久禁写，禁写表放配置。
- **小模型拿到整份事实文件会挑最顺手的数字。** 生成器按 JD 关键词选事实卡的一行，只把该行的项目喂给模型。
- **同一项目锚点限频按当日总量均摊**，不是固定 5 条。固定额度在一天发 100 条时必然卡死，上一轮是靠环境变量硬绕过去的，结果某个项目一天用了 18 次。
- 120–200 字：100 字只够写"我做过 X，按模块报价，能远程吗"，老板看不出和其他人的差别；200 字够写清一个交付事实的做法和验收方式。竞争力在细节不在形容词。
- 第三句只问能不能远程/线上做。对方还没答应合作，追问业务细节不合适。"目前主要做哪类系统"这种不看 JD 也能问的一律拒。
- 禁写"不走坐班/入职/提成"这类防备词，禁写"具备…能力/赋能/一站式/期待合作"这类套话，不分号分点，顿号串最多 3 项。
- 被拒一次把原因喂回去重写一次，第二次仍不过才放弃。

## 5. 去重与送达

- 重复招呼的根因：聊天列表虚拟列表只渲染 40 条，扫屏幕去重必漏。主键是 `encryptBossId`，去重读完整数据源。
- 一个招聘者全局只发一次，同一招聘者发布的不同岗位也跳过。
- 送达核验必须三件同时成立：输入框清空、完整消息属于本人气泡、气泡显示"送达/已读"。缺一记 `delivery_unverified`，复核一次仍不确认就永远不重发。
- 建了会话但没点发送时保存为 `chat_created_not_sent`，恢复时只允许续发同一 JD 绑定的已存文案，不重复计额度。
- `send` 返回非 `not_sent` 状态后，禁止手工把状态改回去。

## 6. 安全与额度

- **岗位详情实测约 1000 次/日封号**（1010 被封、686 无事）。硬顶取 900 留 10% 余量，它是翻车线不是安全线。
- 预算窗口是 24 小时滚动，不是自然日。昨晚 23:00 和今早 00:30 算同一个窗口。
- 慢速串行的批处理仍是固定节奏采集器，"等间隔的串行比并发更像机器"。所有等待用随机区间。
- 禁止模型自己写循环驱动在线动作。唯一例外是 harness 自己的执行器 `dispatch`：它每条照走随机节流、全部门禁和停机条件。当初禁批处理防的是"没有闸门地刷"，不是批量本身。
- 熔断锁是文件，上下文压缩、重启、换模型都清不掉。风控级锁当天拒绝解锁。
- 解锁后只做一次人工监督的最小验证，任何异常立即重新锁定。同一错误第二次就换安全路径；没有安全路径就如实记录。

## 7. 浏览器

- Playwright `connect_over_cdp` 被 BOSS 弹成 about:blank，改裸 CDP。
- 默认 profile 目录不绑定调试端口，要复制到独立 user-data-dir。
- 隐藏桌面上的窗口 `MainWindowHandle` 恒为 0，判断就绪要数该桌面上的窗口数。
- 发送、保存、提交类按钮必须显式 `--allow-action`；简历编辑容器正文里出现"确认/发送"字样不能误判为按钮。
- BOSS 静默通过安全复核后仍把参数留在 URL 上，安全页判定不能只看子串。

## 8. 上下文纪律

- 台账单个岗位约 5KB，几千个岗位直接冲掉上下文窗口。禁止直接读，一切走命令。
- 每个 JD 只读一遍，判完就丢；复看走离线命令，不重新联网烧额度。
- 队列上百条时只印前 20 条会逼模型去翻台账文件，所以筛选留在命令参数里。
- 教训文件按主题改写旧口径，不按日期追加。日期追加的文件几周后没人读得完。

## 已废弃口径

| 旧口径 | 被谁覆盖 |
|---|---|
| 用浏览器插件 / Playwright | 裸 CDP |
| 开场白用固定模板 | 按 JD 自由写 → 三句结构 + 事实门禁 |
| 标题"可远程"但正文无证据 → fail | 未写明 = negotiable |
| 远程/结算证据不全 → 人工复核、禁止发送 | 取消人工复核档 |
| 预算按自然日重置 + 深夜减速 | 24 小时滚动，全天同一速率 |
| 任意理由立即解锁 | 风控级锁满 24 小时且跨自然日 |
| `search --pages=N` 一条命令连续翻页 | 一条命令一页，显式续页 |
| 项目锚点固定 5 次/日 | 按当日总量均摊 |
| 每日指标含回复数，按回复率校准搜索词 | 只报发送数 |
| 一次一个岗位手动发送，模型逐条确认 | `ai-opener --batch` → `send-plan` → `dispatch` |
